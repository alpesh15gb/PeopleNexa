The three workflow owners worked concurrently. Each row records checks on an integrated checkout, so later workflow edits may also be present in earlier builds. Existing API handler lint cleanups preserve their contracts. The change set includes no database migration or production deployment.

## Local acceptance evidence

* **Inventory and presentation.** The [screen ledger](screen-revamp-ledger.md) matches all 71 App Router page paths, including two compatibility redirects. The final standalone production bundle rendered the public, platform, administrator and employee destinations at 1440 and 390 CSS pixels. The browser captured 142 route screenshots, reported no page exceptions and found no document-level horizontal overflow. Redirect targets were checked independently before their destination screenshots. Pages beyond the core workflows reuse their existing route-specific implementations and the refreshed shared UI.
* **Navigation and lists.** Chromium tested keyboard command-palette opening and dismissal, search handoff to the scoped directory, saved directory preferences surviving reload, phone navigation and its More dialog, and service switching from attendance. The shared theme test checked foreground and control contrast against the defined light and dark surfaces.
* **Home and approvals.** A populated 390 px dashboard opened a leave request with dates, reason and approved-team overlap. A decline persisted to PostgreSQL, preserved the branch on return and removed the request after reload. Branch-manager checks also exercised approval, a locked payroll period, stale and foreign-scope links, cancellation decline and a competing cancellation timestamp.
* **Attendance and leave.** The employee calendar opened a day with recorded and held punch evidence. A correction submitted from the day, returned to that date, and updated attendance after manager approval. A leave application excluded a holiday, estimated 12 days becoming 11 and submitted successfully. Historical or changing allocations use a submission-time verification message.
* **People and onboarding.** Browser checks covered six record sections, retained directory filters, masked data, checklist assignment and employee completion, private temporary credential issuance, employee password change, document access restrictions, active policies, assigned assets, home holidays and the latest published personal PDF even with a newer draft. In the credential scenario, the local login throttle required a matching synthetic session to exercise password change. Unhydrated public authentication forms were checked with JavaScript disabled.
* **Payroll.** Chromium completed Check inputs, Adjustments, Variance review and Finalize & disburse at 390 px. A saved bonus changed draft net pay from INR 1,000 to INR 1,100 after server recalculation. The workflow showed the prior-period 22.2% variance and PF, ESI, PT and TDS, resumed after reload, required an independent reviewer, exported the register, recorded an external cash payment fixture and kept the resulting history read-only. The latest employee statement and tax handoff were exercised.
* **Regression coverage.** The 63 TypeScript and CommonJS regression scripts passed, including local transactional attendance checks. The gallery also tested platform plan, seat, license and module changes and loss of access after a synthetic workspace suspension. These tests do not exercise a physical biometric device, actual money movement, outbound mail or a production tenant.

Exact proposed contracts and the fallback used for each unsupported capability are in [Required backend additions](required-backend-additions.md).
